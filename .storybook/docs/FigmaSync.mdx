# Figma ⇄ code sync

Figma is the source of truth for tokens and component variants; code is the source of truth for behaviour. These docs are generated from the bridge files the sync maintains, so they are only as fresh as the last sync.

<SyncSummary />

## How a sync works

1. **Tokens (Figma → code).** The `ad-design-kit-figma-sync` skill exports the Figma variable collections, diffs them against the committed snapshot, rebuilds `ad-design-kit.css` and the token manifest, and copies the CSS into the app (`npm run tokens:build`). The token linter (`npm run lint:tokens`) then flags any class that no longer exists.
2. **Components (Figma → code).** The skill inventories every component page, diffs variant properties and values against the registry (`components.json`), and updates the React components, the prop maps and the usage docs.
3. **Storybook docs.** `npm run docs:build` regenerates this Storybook's data from the registry, usage docs, token manifest and Figma audit. It runs automatically before `npm run storybook`; `npm run docs:check` fails in CI when the docs are stale or drift is found.
4. **Code → Figma** (with explicit approval only): component usage descriptions and Code Connect mappings can be pushed back to the Figma file.

## Registry ↔ code status

Every component set in the registry, its Figma node and whether the React source still matches the registry's prop map. A finding here means the registry, the component or Figma changed without the others following.
